# Skill 自扩展与进化机制

## 目标

让本 Skill 在使用中自动完善，用户无需手动编辑文件。遇到未覆盖的场景时，AI 自动更新 Skill 并在后续对话中生效。

## 触发条件

以下任一情况触发 Skill 更新：

1. **用户明确要求**："给skill加个规则"、"以后xxx的时候要xxx"、"更新协作流程"
2. **AI 发现缺口**：执行任务时遇到 Skill 未覆盖的场景，且该场景具有通用性（不是一次性操作）
3. **用户反馈问题**："这个流程不对"、"以后不要这样做"、"应该先xxx再xxx"
4. **预留方向激活**：用户用到了下方"预留扩展方向"中的功能

## 更新流程

### 自动更新（默认）

适用于新增规则、补充流程、修复不合理之处：

1. 读取当前 SKILL.md 和 references/ 下的相关文件
2. 备份当前版本到 `backups/SKILL-YYYYMMDD-HHMM.md`（同时备份被修改的 references 文件）
3. 在内存中修改内容
4. 自检：
   - YAML frontmatter 格式是否正确（name、description 字段完整）
   - 新规则是否与现有规则矛盾（如"禁止直接推main" vs "可以直接推main"）
   - 章节结构是否完整，有无断裂
   - 引用的 references 文件路径是否存在
   - SKILL.md 是否超过 500 行，超出则将详细内容拆分到 references/
5. 写入文件
6. 告知用户："已更新协作规则：{变更摘要}"，无需用户确认
7. 如果用户后续说"不对，改回去"，执行回滚

### 重大变更需确认

以下情况需先向用户说明变更内容，确认后再写入：
- 修改分支策略或安全红线
- 删除已有规则
- 改变默认行为（如从"必须PR"改为"可以直接推main"）
- 新增需要用户安装额外工具的流程（如 Git LFS、CI/CD）

## 回滚机制

- 备份保留最近 10 个版本，超出自动删除最旧的
- 用户说"回滚skill"时：列出备份版本（带时间和简要差异），用户选择后恢复
- 用户说"回滚到上一版"时：直接恢复最近一次备份
- 回滚本身也会先备份当前版本（防止回滚后又想恢复）

## 预留扩展方向

以下功能当前未启用完整流程，当用户提到相关需求时自动激活并补充到 Skill 中：

| 方向 | 触发信号 | 激活时补充的内容 |
|------|----------|------------------|
| Git LFS | 提到大文件版本管理、psd/zip/二进制资源 | LFS 安装、track 配置、.gitattributes 提交、配额提醒 |
| CI/CD | 提到自动构建、自动测试、自动部署、GitHub Actions | workflow 文件模板、触发条件、secrets 管理 |
| 多环境分支 | 提到 develop/release/hotfix 分支、版本发布流程 | Git Flow 或 GitHub Flow 分支模型、合并顺序 |
| 代码格式化 | 提到 prettier/black/eslint/format、pre-commit | hook 配置、格式化命令、提交前自动检查 |
| CHANGELOG | 提到变更日志、release notes 自动生成 | Keep a Changelog 格式、基于 commit 自动生成 |
| 多协作者 | 提到 CODEOWNERS、分支保护、review 要求 | 权限配置、review 规则、冲突协调 |
| Conventional Commits 校验 | 提到 commitlint、提交信息校验 | commitlint 配置、husky hook |
| Issue/PR 模板 | 提到 issue template、PR template | .github/ 目录下的模板文件 |

激活时：
1. 告知用户"这是预留扩展方向，我现在把完整流程加进Skill"
2. 按更新流程写入
3. 从预留方向表中移除已激活项（或标记为已启用）

## 不自动扩展的情况

以下情况不自动修改 Skill，而是提醒用户手动决定：
- 与安全红线冲突的规则（如"以后允许提交密钥"）
- 需要用户提供账号、token、付费服务的配置
- 针对特定一次性任务的临时流程（不具备通用性）
